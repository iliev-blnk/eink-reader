# IBV book format, v0.1

Status: **draft for review (SPEC-2).** Written 2026-10-26.
Reference implementation: `tools/converter/ibv.py` (reader, writer, validator). Tests: `tools/converter/test_ibv.py`.
Worked example: `spec/examples/example.ibv`, generated by `spec/examples/make_example.py`.

**Name.** IBV, *Ink Book Volume*, which is also the author's initials. Extension `.ibv`, sidecar folder `/.ibv/` (Q5, decided 2026-10-26).

When this document and `ibv.py` disagree, one of them has a bug. Fix it, then add a line to the changelog at the end.

---

## 1. What the format is for

The device never parses EPUB, FB2 or HTML. A PC converter does all of that once and writes this format. The device then only needs to:

1. list books cheaply: read the header and metadata, a few hundred bytes;
2. open a book cheaply: read the block index, a few KB;
3. get the text near any position quickly, with **bounded RAM**: decode at most one block of ≤ 32 KB;
4. lay the text out itself at whatever font size and margins the reader picked, because the format is **reflowable**.

Everything that is expensive or language-specific happens on the PC:
- Unicode normalization
- Romanian ş/ţ → ș/ț
- hyphenation, stored as soft hyphens
- structure detection
- compression, done with the best settings since it runs once

The device does only what depends on the screen: line breaking, justification and pagination.

## 2. Conventions

- All integers are **little-endian**, the ESP32's native order, so the device reads them with plain loads.
- `u8/u16/u32` are unsigned. Offsets are absolute byte offsets from the start of the file, so files are limited to 4 GiB.
- `varint` = unsigned LEB128: 7 bits per byte, low group first, high bit = "more bytes follow". Values must be < 2³², so a varint is at most 5 bytes. Varints appear only inside text blocks, where most values are small.
- Text is **UTF-8, NFC-normalized**.
- `CRC32` is the standard CRC-32 used by zlib, PNG and Ethernet (reflected, polynomial 0xEDB88320, init and final XOR 0xFFFFFFFF). On the device it's `esp_rom_crc32_le()` from ROM.
- `DEFLATE` means raw DEFLATE (RFC 1951) with no zlib or gzip header. On the device it's `tinfl_decompress()` from the ESP32-S3 ROM (`esp32s3.rom.ld:83`), so it takes no flash space.

## 3. File layout

```
offset 0   ┌─────────────────────────────┐
           │ Header              44 B    │  magic, version, book_id, counts, CRCs
       44  ├─────────────────────────────┤
           │ Section directory   16 B × n│  tag, offset, length, CRC32 per section
           ├─────────────────────────────┤
           │ META   metadata             │  title, author, language, …
           │ TOC    table of contents    │  optional
           │ BLKS   block index          │  one 24 B entry per text block
           │ COVR   cover image          │  optional
           │ TEXT   text blocks          │  the content, block after block
           └─────────────────────────────┘
```

The device finds sections only through the directory and never assumes the order shown. The writer uses that order so all the small sections come first: a single 4 KB read usually gets the header, the directory, META and BLKS together.

### 3.1 Header (44 bytes)

| Offset | Size | Field | Value / meaning |
|---:|---:|---|---|
| 0 | 8 | `magic` | `89 49 42 56 0D 0A 1A 0A` = `\x89IBV\r\n\x1a\n` |
| 8 | 1 | `version_major` | 0 |
| 9 | 1 | `version_minor` | 1 |
| 10 | 2 | `header_size` | 44. The directory starts here. Later versions may grow the header; readers skip what they don't know. |
| 12 | 4 | `flags` | 0. Reserved. |
| 16 | 8 | `book_id` | first 8 bytes of SHA-256 over the META payload, then every encoded record in order (see 3.7) |
| 24 | 4 | `paragraph_count` | number of records in the book |
| 28 | 4 | `text_bytes` | sum of every record's text length, in bytes; used for "x %" before pagination is done |
| 32 | 2 | `section_count` | number of directory entries |
| 34 | 2 | reserved | 0 |
| 36 | 4 | `directory_crc` | CRC32 of the whole directory |
| 40 | 4 | `header_crc` | CRC32 of bytes 0–39 |

The magic is borrowed from PNG. The non-ASCII first byte means the file can't be mistaken for text. The `\r\n`, `\x1a` and `\n` bytes catch a file that was mangled by a text-mode copy (line-ending conversion, or truncation at Ctrl-Z).

### 3.2 Section directory (16 bytes per entry)

| Offset | Size | Field |
|---:|---:|---|
| 0 | 4 | `tag`: four ASCII characters, e.g. `META`, `TOC ` (with a space) |
| 4 | 4 | `offset` |
| 8 | 4 | `length` |
| 12 | 4 | `crc32` of the section's bytes |

Rules:
- Required sections: `META`, `BLKS`, `TEXT`. Optional: `TOC `, `COVR`.
- A tag may appear at most once. **Readers skip tags they don't know**, so a newer converter can add sections without breaking older firmware.
- The device checks each section's CRC when it reads the section. The `TEXT` CRC covers the whole content, so only the validator checks it. The device instead checks each block's own CRC when it decodes that block.

### 3.3 `META`: metadata

```
u16 count
count × { u8 key, u16 length, length bytes of UTF-8 }
```

| Key | Name | Required | Example |
|---:|---|:---:|---|
| 1 | title | yes | `Amintiri din copilărie` |
| 2 | author | | `Ion Creangă` |
| 3 | language | yes | BCP 47 tag: `ro`, `ru`, `en` |
| 4 | source | | original file name or URL |
| 5 | converter | | `ibv.py 0.1` |
| 6 | converted | | ISO 8601 date |
| 7 | year | | original publication year, as text |
| 8 | description | | |

Each key appears at most once, and readers skip keys they don't know. The library screen needs only the header and META.

### 3.4 `TOC `: table of contents (optional)

```
u16 count
count × { u32 para, u8 level (1–4), u8 reserved = 0, u16 length, length bytes of UTF-8 title }
```

`para` is the index of the record the entry jumps to, usually a HEADING. Entries are sorted by strictly increasing `para`. Titles are stored without soft hyphens, so the chapter list can be drawn without decoding any blocks. An empty or missing TOC is valid, which is normal for TXT input.

### 3.5 `BLKS`: block index

```
u32 count
count × 24-byte entry:
```

| Offset | Size | Field | Meaning |
|---:|---:|---|---|
| 0 | 4 | `offset` | absolute file offset of the stored block |
| 4 | 4 | `stored_len` | bytes on disk |
| 8 | 2 | `raw_len` | bytes after decoding, **≤ 32768** |
| 10 | 1 | `method` | 0 = stored, 1 = DEFLATE. Other values: the block can't be read. |
| 11 | 1 | reserved | 0 |
| 12 | 4 | `first_para` | index of the block's first record |
| 16 | 4 | `text_start` | total text bytes of all records before this block |
| 20 | 4 | `crc32` | CRC32 of the **decoded** (raw) bytes |

Invariants, all checked by the validator:
- Blocks are back to back. Block 0 starts at the TEXT section's offset, each next block starts where the previous one ends, and the last ends at the end of TEXT.
- `first_para` and `text_start` start at 0 and increase by exactly what the previous block holds. Each block holds `first_para[i+1] − first_para[i]` records; the last one holds `paragraph_count − first_para[last]`.
- Every block holds at least one whole record, and no record is split across blocks.

**Why the CRC covers the decoded bytes:** one check catches a bad SD read, a bug in the converter's compressor and a bug in the device's decompressor. gzip makes the same choice.

### 3.6 `TEXT`: text blocks and records

A block, once decoded, is a sequence of **records**. One record is one paragraph-level item:

```
u8     kind
u8     flags
varint text_len           bytes of UTF-8 text
varint run_count
run_count × { varint start, varint length, u8 style }
text_len bytes of UTF-8 text
```

**Kinds**

| Value | Kind | Text | Default layout |
|---:|---|---|---|
| 0 | PARA | yes | justified, first-line indent |
| 1 | HEADING | yes | centered, larger or bold font, space above, never the last line on a page |
| 2 | VERSE | yes | one line of poetry: left-aligned, not justified. If it's too wide it wraps with a hanging indent. |
| 3 | BREAK | **none** (`text_len` = 0, no runs) | a stanza or scene break: a blank line, or an ornament if flagged. Dropped at the top of a page. |
| 4 | QUOTE | yes | block quote or epigraph: indented on both sides |

A reader that meets an unknown kind with text lays it out as PARA, and skips an unknown kind with no text.

**Flags**

| Bit | Mask | Meaning |
|---:|---:|---|
| 0–1 | `0x03` | alignment: 0 = the kind's default, 1 = left, 2 = center, 3 = right |
| 2 | `0x04` | `NO_INDENT`: no first-line indent (e.g. the first paragraph after a heading). On BREAK the same bit means `ORNAMENT`: draw `* * *` instead of a blank line. |
| 3 | `0x08` | `CONT`: continues the previous record. The converter split an over-long paragraph, so there's no indent and no paragraph spacing; the layout treats the two as one paragraph. |
| 4–5 | `0x30` | HEADING only: level − 1, for levels 1–4 |
| 6 | `0x40` | reserved, 0 |
| 7 | `0x80` | reserved, must be 0; the validator rejects it |

**Style runs** mark byte ranges `[start, start + length)` of the text, in the record's own UTF-8 bytes. Runs are sorted, never overlap, and never split a UTF-8 sequence. Text no run covers is regular, and a run with style 0 is invalid. Style bits: `0x01` bold, `0x02` italic. Other bits are reserved and ignored by readers.

**Text rules.** These are what make on-device layout simple:
- No C0 or C1 control characters: no tabs or newlines.
- Single spaces between words, none at either end.
- Special characters the converter inserts and the layout engine must honour:
  - `U+00AD` soft hyphen: an allowed break point. Draw "-" only if the line breaks there; otherwise it's invisible.
  - `U+00A0` no-break space: a space that must not break. The converter ties a dash to the word before it so no line starts with "—".
  - `U+200B` zero-width space: an allowed break point with no hyphen, e.g. inside long URLs.
  - `U+2028` line separator: a forced line break inside a paragraph (an XHTML `<br/>`).

**Block size.** `raw_len` is at most **32768** bytes. That's the size of the DEFLATE window, so the device decodes a whole block into one fixed 32 KB buffer, and that buffer also serves as the decompressor's dictionary. Within the cap, the converter fills blocks greedily with whole records up to a target size: 16384 by default, `--block` to change it. Choosing the default is part of experiment E5. A paragraph whose record would be bigger than 32 KB is split at a space by the converter, and the later parts are marked `CONT`. Each block is stored raw (method 0) when DEFLATE wouldn't make it smaller.

### 3.7 Positions and `book_id`

A reading position is the pair **(paragraph index, byte offset in that paragraph's text)**. The byte offset always lands on a UTF-8 character boundary.

Positions don't depend on the font, the screen or the block layout. Pagination changes with the settings, but the position stays the same, so after a settings change the reader re-paginates around the same sentence.

`book_id` hashes the META payload and the **encoded records, before compression**. So converting the same book with a different block size or compression gives the same `book_id`, and saved positions stay valid. Changing anything in the text, including hyphenation, gives a new `book_id`. The firmware then knows the old byte offsets may point to the wrong place. The ID is 64-bit, so an accidental collision between books on one card is not a practical concern.

### 3.8 `COVR`: cover (optional)

```
u16 width, u16 height      at most 240 × 416 (portrait screen)
u8  method                 0 = stored, 1 = DEFLATE
u8  reserved = 0
u32 raw_len                = ceil(width / 8) × height
bitmap (stored or DEFLATE)
```

The bitmap is 1 bpp, row-major, rows padded to whole bytes, MSB = leftmost pixel, **bit 1 = white**. That's the UC8253 panel RAM layout and the firmware's `gfx_t` framebuffer layout, so a full-screen cover is copied straight to the panel. The converter scales the image and dithers it (Floyd–Steinberg, CONV-6).

## 5. How the device reads a book

**Library.** For each `.ibv` file on the card:
1. Read the first 44 bytes, check the magic, version and `header_crc`.
2. Read the directory and check `directory_crc`.
3. Read META.

The cover is read only for the sleep screen.

**Open.**
1. Read BLKS (24 B per block; *Moara cu noroc* has 17 blocks at 16 KB, so about 400 B) and check its CRC.
2. Load the position from the sidecar file (section 6).
3. Find the block holding paragraph *p* by binary search on `first_para`.

**Read a block.** Read `stored_len` bytes and inflate them into the 32 KB buffer (method 1), or read them straight into it (method 0). Check `crc32` against the raw bytes. Then walk the records: each one's length is in its header, so the walk needs no index.

**RAM budget for the book reader:**

| | |
|---|---|
| block buffer | 32 KB |
| `tinfl` decompressor state | ~11 KB |
| block index | 24 B × blocks |
| read buffer for the stored block | ≤ 32 KB, or streamed in 4 KB pieces |

That's under 80 KB of the S3's 512 KB SRAM in all, and **independent of the book's length**. No PSRAM is needed. A second block buffer is optional. It lets a page that crosses a block boundary, or a "previous page" at the start of a block, avoid decoding twice. The firmware decides that after E2.

**Progress.** Before pagination finishes:

> % = (`text_start` of the block + bytes before the position in the block) / `text_bytes`

After pagination it's "page x of y".

**Corruption.** A failed header, directory or section CRC means the device shows "damaged file" in the library and doesn't open the book. A failed block CRC means it shows an error page in place of that block's text and lets the reader skip past it. One bad sector shouldn't make the whole book unreadable.

## 6. Sidecar files

The device writes per-book state next to the books, but never into the book file. The book stays exactly as the converter wrote it, and the validator still passes after months of reading.

Sidecars live in `/.ibv/` on the card and are named after the `book_id` in hex, not the book's file name. Renaming or moving a book on the PC keeps its progress, and the books folder stays clean when you browse the card. *(This changes the plan, which had `<book>.pos` next to each book.)* FATFS long file names must be enabled; ESP-IDF supports them.

Every sidecar starts with a 4-byte magic and the 8-byte `book_id` and ends with a CRC32 of everything before it. If the CRC or `book_id` doesn't match, the device ignores the file: no progress is better than a wrong position.

**Writes are atomic:** the device writes `<name>.tmp`, then renames it over the old file. A power cut mid-write leaves the old file intact.

| File | Layout | Written when |
|---|---|---|
| `<id>.pos` | `"IPOS"`, book_id, u32 para, u32 byte, crc32 → 24 B | on sleep, on closing the book, and every N page turns |
| `<id>.bm` | `"IBMK"`, book_id, u16 count, count × {u32 para, u32 byte}, crc32 | on adding or removing a bookmark |
| `<id>-<layout>.pg` | `"IPGC"`, book_id, u32 layout_hash, u32 page_count, u8 complete, 3 B reserved, page_count × {u32 para, u32 byte}, crc32 | by the background paginator, as it goes |

`layout_hash` covers everything that changes where pages break:
- font file and size
- margins
- line spacing
- hyphenation on or off
- the layout engine's own version number

Changing any setting means a different `.pg` file. The device keeps the most recent few and deletes the rest. `complete = 0` means pagination is still running: page numbers show as "≈" until it finishes.

## 7. Validator rules

`ibv.py validate` checks the following and exits non-zero on any failure. CONV-10 runs it over the whole corpus.

1. Magic, major version, `header_size`, `header_crc`, `directory_crc`.
2. No duplicate tags. Every section lies inside the file. Every section CRC matches, TEXT included. META, BLKS and TEXT are present.
3. META has a title and a language, and no key twice.
4. Every BLKS invariant in 3.5. Every block decodes to exactly `raw_len` bytes, its CRC matches, and its records end exactly at the end of the block.
5. Every record:
   - known flag bits only
   - BREAK has no text
   - other kinds have non-empty text
   - valid UTF-8, NFC-normalized
   - no control characters
   - no leading, trailing or doubled spaces
   - runs sorted, non-overlapping, in range, on character boundaries, style ≠ 0
6. `paragraph_count`, `text_bytes` and `book_id` match the content.
7. TOC entries are in strictly increasing order and in range, with levels 1–4.
8. The cover is at most 240 × 416.

The tests (`test_ibv.py`) flip every single bit of a sample file one at a time and check that the validator catches every one. The first run of that test found that a damaged directory tag went unnoticed, because unknown sections are skipped by design. That's why `directory_crc` exists.

## 8. Versioning

- **Major** version: a reader refuses any major version it doesn't know.
- **Minor** version: only compatible additions, such as new sections, META keys, kinds or style bits. Readers already ignore those by the rules above.
- During **0.x**, anything may change. The format freezes as **1.0** once the converter, the validator, the simulator and the firmware all implement it (SPEC-4). After that, every change bumps a version.

## 9. Design choices, and the alternatives turned down

| Choice | Alternative | Why |
|---|---|---|
| Reflowable records | Pre-paginated pages | The layout engine is a must-do, and font size must be adjustable. Pre-paginated output would lock each file to one font and size. |
| Hyphenation in the converter (soft hyphens) | Hyphenation patterns on the device | Liang's patterns for RO + RU + EN are large, and the PC has unlimited time. The device only needs to break lines. Cost: soft hyphens make the raw text **18.5 % bigger** on *Moara cu noroc* (2 bytes each). |
| Blocks of ≤ 32 KB, compressed independently | One DEFLATE stream per chapter, as the master plan first said | A chapter has no size limit: a TXT book is one chapter, and *Moara cu noroc*'s longest chapter is 37 KB, already past the 32 KB DEFLATE window. Seeking into a DEFLATE stream means decoding from its start. Blocks make both the RAM use and the seek time constant. **This replaces "compression per chapter" in the master plan.** |
| DEFLATE | LZ4, heatshrink, none | The decoder is already in the ESP32-S3 ROM, so it costs zero flash, and DEFLATE compresses text better than LZ4. E5 measures decode time on the device. |
| Varints inside records | Fixed u16/u32 | Most lengths are under 128, so 1 byte instead of 4. Header fields stay fixed-width so they're easy to read and seek. |
| Section directory with tags | Fixed layout | Readers skip unknown sections, so v0.x firmware keeps working with newer files: the same idea as PNG chunks and TrueType tables. |
| Position = (paragraph, byte) | Page number, or a global byte offset | Survives font and setting changes. The global byte offset would also survive, but the pair goes straight to the block lookup. |
| `book_id` over uncompressed content | Hash of the file, or the file name | Survives re-blocking, recompression and renaming, and changes exactly when the text changes. |

## 10. Preliminary numbers

These come from the four mockup books (`docs/mockup/texts/*.hy.txt`), run through `ibv.py` on the PC on 2026-10-26. They aren't E5 yet: E5 uses the 20-book corpus and adds on-device timings. They're here to show that the design is in a sensible range.

| Book | Plain text | gzip -9 (whole file) | IBV stored | IBV, 4 KB blocks | 8 KB | **16 KB** | 32 KB | Blocks at 16 KB |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Amintiri din copilărie (RO) | 153,945 | 59,734 | 185,619 | 89,520 | 82,289 | **76,816** | 72,298 | 12 |
| Moara cu noroc (RO) | 227,663 | 77,922 | 272,075 | 125,290 | 114,245 | **105,269** | 97,948 | 17 |
| Luceafărul (RO, verse) | 11,619 | 4,920 | 12,398 | 6,270 | 5,943 | **5,549** | 5,549 | 1 |
| Белые ночи (RU) | 183,416 | 48,628 | 211,813 | 77,201 | 70,962 | **64,862** | 60,175 | 14 |

Sizes are in bytes. Plain text means the source with soft hyphens removed.

- At 16 KB, a book is **35–50 % of the plain text**, and about 1.3× what gzip gets compressing the whole file as one stream. That 1.3× is the price of random access plus the soft hyphens.
- 32 KB blocks save another 6–8 %, but double the worst-case decode on every seek. Whether that's worth it depends on the inflate time per block on the device. That's E5's question, together with E2.
- Questions for E5: the soft-hyphen overhead could be removed by storing break points as a bit list per record. That's smaller, but it makes the layout engine's text walk more complex. Measure before deciding.

## 11. Not in v0.1 (candidates for later)

- Footnotes and endnotes. EPUB has them; they need a link target plus a "notes" view.
- Images inside books. These are a non-goal for v1; only the cover is supported.
- Small caps, superscript, subscript: the style bits are free.
- Per-book font hints, e.g. "this book needs Greek".
- Internal links, beyond what the TOC already gives.
